## Slide Page 3

13.3
IoT design methodology

### รายละเอียดไดอะแกรม: IoT Design Methodology (Bahga & Madisetti)
กระบวนการออกแบบเชิงวิศวกรรม 10 ขั้นตอนแบบบนลงล่าง (Top-Down 10-Step Methodology):
1. **Purpose & Requirements**: กำหนดวัตถุประสงค์ ขอบเขตระบบ ความต้องการเชิงฟังก์ชัน และพฤติกรรมของระบบ
2. **Process Model Specification**: กำหนด Use Cases และโมเดลกระบวนการทำงานทางธุรกิจ
3. **Domain Model Specification**: กำหนดเอนทิตีจริง (Physical Entities), เอนทิตีเสมือน (Virtual Entities), อุปกรณ์ (Devices), ทรัพยากร (Resources) และบริการ (Services)
4. **Information Model Specification**: กำหนดโครงสร้างข้อมูล ความสัมพันธ์ (Relations) และแอตทริบิวต์ (Attributes) ทั้งหมดของระบบ
5. **Service Specifications**: แมป Process และ Information Model เข้ากับบริการ กำหนด Endpoint, Input, Output
6. **IoT Level Specification**: เลือกระดับความซับซ้อนของสถาปัตยกรรม (IoT Level 1 ถึง 6)
7. **Functional View Specification**: จัดกลุ่มฟังก์ชันตาม Functional Groups (Device, Communication, Services, Management, Security, Application)
8. **Operational View Specification**: กำหนดเทคโนโลยีสื่อสาร (Communication), โฮสติ้ง (Hosting), ที่จัดเก็บข้อมูล (Storage) และฮาร์ดแวร์
9. **Device & Component Integration**: ประกอบและเชื่อมต่ออุปกรณ์ เซนเซอร์ แอคชูเอเตอร์ และซอฟต์แวร์คอมโพเนนต์
10. **Application Development**: พัฒนาแอปพลิเคชัน อินเทอร์เฟซผู้ใช้ (Web/Mobile App) สำหรับควบคุมและแสดงผล

## Slide Page 14

13.14
Design Patterns for IoT with examples
Design patterns are structured solutions to 
common problems in software design. The 
patterns help address unique challenges such 
as scalability, reliability, and security. Here are 
some key design patterns for IoT, along with 
explanations and examples:


---

## Slide Page 15

13.15
1. Observer Pattern
When one object (the subject) changes 
state, all its dependents (observers) are 
notified and updated automatically. This 
pattern is useful for IoT systems where 
multiple devices need to react to state 
changes in another device or service.


---

## Slide Page 16

13.16
Example:
A smart home system where the central hub 
(subject) broadcasts changes in temperature to 
all connected thermostats (observers). When 
the central hub detects a temperature change, 
it notifies all thermostats to adjust their 
settings accordingly.


---

## Slide Page 17

13.17
2. Gateway pattern
The gateway handles data aggregation, 
preprocessing, and protocol translation, 
ensuring that devices with different 
communication protocols can interact with 
each other and the cloud.
Gateway device can bridge communication 
between IoT devices and external networks.


---

## Slide Page 18

13.18
Example:
In an industrial IoT setup, various sensors (e.g., 
temperature, humidity, and pressure sensors) 
use different communication protocols. A 
gateway device collects data from these 
sensors, converts it into a unified format, and 
sends it to a cloud server for further analysis.


---

## Slide Page 19

13.19
3. Publish-Subscribe
Publishers send messages to a broker, 
which then distributes the messages to 
subscribers based on their interests. 
For scalable and flexible communication in 
IoT systems.


---

## Slide Page 20

13.20
Example:
A smart city application where various sensors
(publishers) send data to a central message 
broker. Traffic management systems, 
environmental monitoring systems, and public 
safety systems (subscribers) receive relevant 
data from the broker to make real-time 
decisions.


---

## Slide Page 21

13.21
4. Proxy pattern
It provides a surrogate or placeholder for 
another object to control access to it. In IoT, 
proxies can help manage communication with 
remote or resource-constrained devices, 
providing a local interface to interact with 
these devices.


---

## Slide Page 22

13.22
Example:
A remote health monitoring system where a 
proxy on a local server interacts with wearable 
health devices (e.g., heart rate monitors) on 
behalf of a central healthcare server. The proxy 
handles intermittent connectivity and data 
caching to ensure reliable communication.


---

## Slide Page 23

13.23
5. Command pattern encapsulates a request 
as an object, thereby allowing for 
parameterization of clients with queues, 
requests, and operations. 
This pattern is useful for executing 
commands on IoT devices and can support 
undoable operations.


---

## Slide Page 24

13.24
Example:
In a smart lighting system, a user can create 
command objects to turn lights on or off, 
adjust brightness, or change colors. These 
command objects can be queued and executed 
by the lighting controller, allowing for complex 
automation and scheduling.


---

## Slide Page 25

13.25
6. State pattern allows an object to alter its 
behavior when its internal state changes. The 
object will appear to change its class. This is 
particularly useful for IoT devices that need to 
behave differently based on their states.


---

## Slide Page 26

13.26
Example:
A smart lock system that changes its behavior 
based on its state (locked, unlocked, or 
jammed). When the state changes, the lock 
system adjusts its responses to user inputs or 
security events accordingly.


---

## Slide Page 27

13.27
7. Chain of Responsibility pattern passes a 
request along a chain of handlers. Each 
handler decides either to process the request 
or to pass it to the next handler in the chain. 
This pattern is useful for handling events or 
commands in IoT systems.


---

## Slide Page 28

13.28
Example:
In a smart home security system, different 
components (e.g., door sensors, motion 
detectors, and cameras) handle security alerts. 
An alert is passed along the chain of devices, 
each adding relevant information until it 
reaches the central security controller, which 
takes the appropriate action.


---

## Slide Page 29

13.29
Best Practices for Implementing IoT Design 
Patterns
Implementing design patterns in IoT 
systems requires careful consideration to 
ensure efficiency, scalability, and security. 
Here are some best practices to follow when 
applying IoT design patterns:


---

## Slide Page 30

13.30
Understand the Requirements and Constraints:
Analyze Use Cases: Thoroughly understand the 
specific requirements such as data volume, 
latency, device capabilities, and network 
conditions.
Example: For a smart home system, determine the 
need for real-time response versus periodic updates, 
considering device power limitations and network 
reliability.


---

## Slide Page 31

13.31
Select Appropriate Patterns:
Match Patterns to Problems: Choose design 
patterns that best address the specific 
challenges of IoT project. Avoid 
overcomplicating the design with unnecessary 
patterns.
Example: Use the Publish-Subscribe pattern for a smart city 
application to manage the high volume of sensor data and 
ensure scalable data distribution.


---

## Slide Page 32

13.32
Ensure Security and Privacy:
Implement Security Measures: Integrate 
security patterns and best practices such as 
encryption, authentication, and access control 
within your design patterns to protect data 
and devices.
Example: In a remote health monitoring system, use the 
Proxy pattern with secure communication channels and data 
encryption to protect sensitive patient data.


---

## Slide Page 33

13.33
Optimize for Scalability:
Design for Growth: Ensure IoT architecture can 
scale horizontally by adding more devices and 
services without significant redesign. 
Example: In an industrial IoT setup, implement the Gateway 
pattern to manage data from a growing number of sensors 
and devices, ensuring efficient data aggregation and 
processing.


---

## Slide Page 34

13.34
Consider Interoperability:
Support Multiple Protocols: Design systems to 
handle various communication protocols and 
data formats, enhancing interoperability 
between different IoT devices and platforms.
Example: Use the Gateway pattern in smart agriculture to 
connect sensors and actuators using different protocols (e.g., 
Zigbee, LoRaWAN) and translate data for cloud processing.


---

## Slide Page 35

13.35
Maintain Flexibility and Modularity:
Use Modular Design: Implement design patterns 
in a modular way to allow easy updates, 
maintenance, and replacement of components 
without affecting the entire system.
Example: In a smart lighting system, use the Command 
pattern to modularize control commands, allowing easy 
updates to the command logic without changing the entire 
control system.


---

Challenges with implementing these design 
patterns
Example of some of the challenges and the

## Slide Page 37

13.37
Interoperability:
Challenge: Ensuring different devices and 
platforms work together seamlessly can be 
difficult due to varied protocols and data 
formats.
Solution: Use standard protocols and data 
formats wherever possible, and implement 
gateways or translators to handle differences.


---

## Slide Page 38

13.38
Security and Privacy:
Challenge: Securing IoT devices and data is 
crucial but challenging due to resource 
constraints and the diverse nature of IoT 
ecosystems.
Solution: Implement security best practices 
such as encryption, authentication, and regular
security updates.


---

## Slide Page 39

13.39
Resource Constraints:
Challenge: IoT devices often have limited 
processing power, memory, and energy, which 
can restrict the implementation of complex 
design patterns.
Solution: Optimize code and use lightweight 
protocols and algorithms tailored for 
constrained environments.


---

## Slide Page 40

13.40
Network Reliability:
Challenge: IoT devices often operate in 
environments with unreliable network 
connectivity, impacting communication and 
data consistency.
Solution: Implement mechanisms for local 
processing, caching, and retry logic to handle 
network issues.


---

## Slide Page 41

13.41
Maintenance and Updates:
Challenge: Updating and maintaining a large 
number of IoT devices can be challenging, 
especially in remote or difficult-to-access 
locations.
Solution: Design systems with over-the-air 
(OTA) update capabilities and ensure 
modularity to facilitate easy updates.

### รายละเอียดสถาปัตยกรรม SMART FARMING สำหรับเกษตรในร่ม (Indoor Agriculture / Greenhouse)
**องค์ประกอบหลักที่ต้องมี:**
1. **สถานีตรวจวัดปัจจัยภายในโรงเรือน:** เซนเซอร์วัดอุณหภูมิ ความชื้น สภาวะแสง เชื่อมต่อไร้สาย
2. **สถานีตรวจวัดปัจจัยภายนอกโรงเรือน (Weather Station):** เซนเซอร์ตรวจวัดสภาพอากาศ ทิศทางลม แสงแดด พร้อมแผงโซลาร์เซลล์
3. **เครือข่ายส่งข้อมูล (Internet / Wi-Fi):** รับส่งข้อมูลไร้สายแบบเรียลไทม์
4. **ระบบคอมพิวเตอร์และ Cloud Software:** จัดเก็บ ประมวลผล แสดงผลแดชบอร์ด และวิเคราะห์ข้อมูล
**ประโยชน์และการทำงาน:** วางแผนกิจกรรมอัตโนมัติ (รดน้ำ ใส่ปุ๋ย ระบายความร้อน เสริมแสงพืช) มีฟังก์ชันพยากรณ์อากาศล่วงหน้าเพื่อปรับสภาพแวดล้อมภายในโรงเรือนแบบเรียลไทม์
