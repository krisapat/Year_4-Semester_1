# สรุปเนื้อหาเจาะลึกและคลังข้อสอบหลอก: บทที่ 3 Problem Statement, User Persona & User Journey

> รวบรวมจากเอกสารการบรรยาย 37 หน้า สกัดกรอบแนวคิด 5W1H, สูตร POV, โครงสร้าง Persona, Empathy Map, 4 ประเภท Pain Points และมิติของ User Journey Map พร้อมจุดลวงในข้อสอบ

## ส่วนที่ 1: สรุปเนื้อหาเจาะลึกรายหัวข้อ (Comprehensive Summary)

### 1. การกำหนดกรอบปัญหา (Problem Statement Framing)
Problem Statement คือเข็มทิศของการออกแบบ UX หากตั้งปัญหาผิด การแก้ปัญหาทั้งหมดจะไร้ประโยชน์:
- **หลักการ 5W1H:**
  - **Who (ใคร):** ใครคือผู้ประสบปัญหาอย่างแท้จริง (ระบุให้ชัดเจน ไม่ระบุกว้างเกินไป เช่น ไม่ใช่ "คนไทยทุกคน" แต่เป็น "พนักงานออฟฟิศมือใหม่ที่เริ่มทำงาน")
  - **What (เกิดอะไรขึ้น):** ปัญหาหรืออุปสรรคที่เกิดขึ้นคืออะไร
  - **Where (ที่ไหน):** สภาพแวดล้อมหรือบริบทที่ปัญหาเกิดขึ้น (เช่น ในรถไฟฟ้าที่สัญญาณเน็ตขาดๆ หายๆ)
  - **When (เมื่อไหร่):** เกิดขึ้นตอนไหน ในขั้นตอนใดของกระบวนการ
  - **Why (ทำไม):** ทำไมสิ่งนี้จึงเป็นปัญหา และส่งผลกระทบอย่างไรต่อชีวิตหรืออารมณ์ของผู้ใช้
  - **How (อย่างไร):** ปัจจุบันผู้ใช้พยายามแก้ไขปัญหาหรือหลบเลี่ยงปัญหานั้นอย่างไร (Workaround)
- **สูตรการเขียน Point of View (POV):**
  $$\text{[User/Persona]} + \text{needs} + \text{[User's Need]} + \text{because} + \text{[Surprising Insight]}$$
  - *ข้อควรระวังขั้นวิกฤต:* ในส่วนของ **Need ต้องเป็น "ความต้องการเชิงเป้าหมาย (Goal)" ห้ามใส่ "วิธีการแก้ปัญหาทางเทคนิค (Solution)" ลงไปเด็ดขาด** (เช่น ห้ามเขียนว่า "ผู้ใช้ต้องการแอปพลิเคชัน..." เพราะแอปพลิเคชันคือโซลูชัน ไม่ใช่ Need)
- **การแปลงเป็นคำถาม How Might We (HMW):**
  - นำ POV มาเปลี่ยนเป็นประโยคคำถามเปิด เช่น "เราจะช่วยให้ [User] สามารถ [Goal] ได้อย่างไร ในระหว่างที่ [Constraint]?"

### 2. ตัวแทนผู้ใช้จำลอง (User Persona)
- **นิยามที่ถูกต้อง:** บุคคลสมมุติ (Fictional Character) ที่สร้างขึ้นจาก **ข้อมูลการวิจัยจริง (Data-driven from Real Research)** ไม่ใช่การนั่งเทียนหรือจินตนาการขึ้นมาเองตามความชอบของดีไซเนอร์
- **กระบวนการสร้าง 3 ขั้นตอน:**
  1. **Data Gathering:** การเก็บข้อมูลจริงผ่านการสัมภาษณ์เชิงลึก (In-depth Interviews), แบบสอบถาม, และการสังเกต
  2. **Analysis & Synthesis:** การจัดกลุ่มพฤติกรรม (Pattern Finding) ด้วย Affinity Diagram
  3. **Persona Creation:** สังเคราะห์ออกมาเป็นตัวแทนของกลุ่มเป้าหมาย
- **องค์ประกอบหลักของ Persona คุณภาพสูง:**
  - **Demographics:** ชื่อ รูปภาพ อายุ อาชีพ รายได้ การศึกษา ที่อยู่อาศัย (เพื่อสร้าง Empathy ให้ทีมเห็นภาพตรงกัน)
  - **Bio & Context:** บริบทการใช้ชีวิต ไลฟ์สไตล์ และเงื่อนไขข้อจำกัด
  - **Goals & Motivations:** สิ่งที่ต้องการบรรลุ ทั้งเป้าหมายในชีวิตและเป้าหมายในการใช้ผลิตภัณฑ์
  - **Pain Points & Frustrations:** อุปสรรคและความคับข้องใจที่พบในปัจจุบัน
  - **Behaviors & Tech Habits:** ความคุ้นเคยกับเทคโนโลยี อุปกรณ์ที่ใช้ และพฤติกรรมประจำวัน
- **ข้อผิดพลาดคลาสสิกในการสร้าง Persona:**
  - **Proto-Persona ที่ไม่ได้รับการตรวจสอบ:** การสร้าง Persona จากสมมติฐานของคนในทีมแล้วนำไปใช้งานจริงโดยไม่ไปสัมภาษณ์ผู้ใช้จริง
  - **Irrelevant Details:** การใส่ข้อมูลที่ไม่เกี่ยวข้องกับบริบทของผลิตภัณฑ์ (เช่น ระบุว่าชอบกินชานมไข่มุกใน Persona ของโปรแกรมคำนวณโครงสร้างวิศวกรรม)

### 3. แผนที่ความเข้าอกเข้าใจ (Empathy Map)
เครื่องมือจัดระเบียบความคิดและพฤติกรรมของผู้ใช้ แบ่งเป็น 4 ช่องหลัก:
- **Says (สิ่งที่ผู้ใช้พูด):** คำพูด ประโยค หรือคำบ่นที่ผู้ใช้พูดออกมาตรงๆ ระหว่างการสัมภาษณ์ (มักใส่เป็นเครื่องหมายคำพูด "... ")
- **Thinks (สิ่งที่ผู้ใช้คิด):** ความคิด ความเชื่อ ความกังวล หรือทัศนคติที่อยู่ในใจ (บางครั้งไม่กล้าพูดออกมาตรงๆ)
- **Does (สิ่งที่ผู้ใช้ทำ):** พฤติกรรมที่สังเกตเห็นได้จริง การกระทำ และการโต้ตอบกับระบบ
- **Feels (สิ่งที่ผู้ใช้รู้สึก):** อารมณ์ ความรู้สึก (เช่น กังวล หงุดหงิด มั่นใจ ภูมิใจ)
- **จุดตายที่ต้องจับสังเกต:** ความขัดแย้งระหว่าง **Says vs Does** (สิ่งที่พูดไม่ตรงกับสิ่งที่ทำ เช่น ผู้ใช้บอกว่า "ชอบฟังก์ชันค้นหาขั้นสูงมาก" แต่เมื่อทดสอบจริงกลับไม่เคยกดใช้งานเลยแม้แต่ครั้งเดียว)

---

### 4. แผนผังการเดินทางของผู้ใช้ (User Journey Map)
แผนผังจำลองประสบการณ์ของผู้ใช้ตั้งแต่จุดเริ่มต้นจนบรรลุเป้าหมาย ประกอบด้วย 5 มิติหลัก:
1. **Persona:** ระบุว่าการเดินทางนี้เป็นของใคร (User คนละ Persona จะมี Journey ที่ต่างกันโดยสิ้นเชิง)
2. **Process / Stages:** ลำดับขั้นตอนหลักในแต่ละช่วง (เช่น Trigger -> Search -> Compare -> Checkout -> After-sales)
   - *Trigger:* เหตุการณ์หรือสิ่งเร้าที่จุดประกายให้ผู้ใช้ต้องเริ่มทำกิจกรรม
3. **Actions / User Behavior:** สิ่งที่ผู้ใช้กระทำจริงในแต่ละขั้นตอน
4. **Emotions & Pain Points:**
   - *Emotion Curve:* กราฟคลื่นอารมณ์บวก/ลบ
   - **4 ประเภทของ Pain Points ในระบบ:**
     * **Productivity Pain Point:** อุปสรรคที่ทำให้เสียเวลา ทำงานได้ช้า เกิดความล่าช้าโดยไม่จำเป็น
     * **Support Pain Point:** ไม่ได้รับความช่วยเหลือในเวลาที่ต้องการ ข้อมูลไม่ชัดเจน ไม่มีคู่มือ ไม่มีช่องทางติดต่อแอดมิน
     * **Process Pain Point:** ขั้นตอนซับซ้อน ยุ่งยาก กรอกข้อมูลซ้ำซ้อน มีหลายขั้นตอนเกินความจำเป็น
     * **Design Pain Point:** ความบกพร่องของ UI ตัวหนังสือเล็กเกินไป สีคอนทราสต์ต่ำ หาปุ่มไม่เจอ เมนูนำทางสับสน
5. **Ideas & Impact:**
   - *Idea:* แนวทางแก้ไขปัญหาหรือฟังก์ชันการใช้งานที่เสนอขึ้นมาเพื่อลบ Pain Point
   - *Impact:* การประเมินผลกระทบเชิงบวกต่อผู้ใช้และคุณค่าทางธุรกิจ

## ส่วนที่ 2: คลังข้อสอบปรนัยประยุกต์และจุดหลอก (10 Tricky Exam Questions)

### ข้อที่ 1 (กับดัก: การเขียน Problem Statement / POV)
**โจทย์:** ข้อใดต่อไปนี้คือประโยคระบุปัญหา (Problem Statement / POV) ที่เขียนได้ถูกต้องตามหลักการของ User-Centered Design มากที่สุด?
- ก. ทีมพัฒนาของเราจำเป็นต้องสร้างแอปพลิเคชันบนมือถือที่มีระบบ AI แนะนำร้านอาหาร เพื่อเพิ่มยอดขายให้กับบริษัท
- ข. ผู้สูงอายุที่อยู่บ้านคนเดียวต้องการสั่งอาหารเพื่อสุขภาพผ่านสมาร์ทโฟน แต่ระบบแอปปัจจุบันมีปุ่มชำระเงินที่ซ่อนอยู่ลึก
- ค. มนุษย์เงินเดือนมือใหม่ต้องการวิธีบริหารจัดการเงินออมที่มีประสิทธิภาพ เพราะพวกเขาไม่มีเวลาศึกษาเรื่องกองทุนและกลัวความเสี่ยงจากการขาดทุน
- ง. นักศึกษาต้องการระบบเว็บไซต์ลงทะเบียนเรียนใหม่ที่ใช้เซิร์ฟเวอร์ Cloud เพื่อไม่ให้ระบบล่มในวันเปิดเทอม

**เฉลย:** **ค. มนุษย์เงินเดือนมือใหม่ต้องการวิธีบริหารจัดการเงินออมที่มีประสิทธิภาพ เพราะพวกเขาไม่มีเวลาศึกษาเรื่องกองทุนและกลัวความเสี่ยงจากการขาดทุน**
- **จุดหลอกของข้อสอบ:** นักศึกษามักเลือกข้อ ก. หรือ ง. เพราะดูมีเทคโนโลยีทันสมัย (AI, Cloud)
- **ทำไมข้อ ค. จึงถูกต้อง:** เป็นข้อเดียวที่เขียนตรงตามโครงสร้าง POV: `[User] + needs + [Need] + because + [Insight]` โดยที่ Need (วิธีบริหารเงินออม) เป็น "เป้าหมาย" ไม่ได้ผูกขาดกับเทคโนโลยี และมี Insight ที่แสดงเหตุผลเชิงจิตวิทยาอย่างแท้จริง
- **ทำไมข้ออื่นถึงผิด:** ข้อ ก. เขียนจากมุมมองของทีมธุรกิจไม่ใช่ User, ข้อ ข. ขาดองค์ประกอบ Insight, ข้อ ง. กระโดดไปล็อก Solution (ระบบเว็บที่ใช้เซิร์ฟเวอร์ Cloud) ซึ่งผิดหลักการระบุปัญหา

### ข้อที่ 2 (กับดัก: Empathy Map - Says vs Thinks vs Does)
**โจทย์:** ในการทดสอบและสัมภาษณ์ผู้ใช้เพื่อพัฒนาแอปพลิเคชันวางแผนการออกกำลังกาย ผู้เข้าร่วมทดสอบให้ข้อมูลว่า "ฉันเป็นคนที่จริงจังกับการคุมอาหารและออกกำลังกายเป็นประจำทุกเช้า" แต่เมื่อผู้ทดสอบขอเปิดดูประวัติการสั่งอาหารย้อนหลังในรอบ 1 สัปดาห์ กลับพบว่ามีการสั่งฟาสต์ฟู้ดและของหวานรอบดึกถึง 5 วัน พฤติกรรมการสั่งของหวานรอบดึกดังกล่าวควรถูกจัดลงในช่องใดของ Empathy Map?
- ก. Says
- ข. Thinks
- ค. Does
- ง. Feels

**เฉลย:** **ค. Does**
- **จุดหลอกของข้อสอบ:** บางคนอาจตอบ Thinks หรือ Feels เพราะคิดว่าเป็นความต้องการตามใจปาก
- **คำอธิบาย:** "สิ่งที่ผู้ใช้พูด" (ฉันจริงจังกับการคุมอาหาร) จัดอยู่ในช่อง **Says** แต่ "การกระทำและพฤติกรรมที่เกิดขึ้นจริงและตรวจสอบได้" (การสั่งของหวานรอบดึก) ต้องจัดอยู่ในช่อง **Does** ซึ่งนี่คือตัวอย่างคลาสสิกของช่องว่างระหว่าง Says vs Does ที่ดีไซเนอร์ต้องจับตามอง

### ข้อที่ 3 (กับดัก: 4 Types of Pain Points - Process vs Productivity)
**โจทย์:** ในเว็บไซต์ขอใบอนุญาตของหน่วยงานราชการ ผู้ใช้ต้องพิมพ์กรอกชื่อ นามสกุล เลขบัตรประชาชน และที่อยู่เดิมซ้ำกันถึง 4 หน้าในแบบฟอร์ม ส่งผลให้ผู้ใช้ต้องเสียเวลาเพิ่มขึ้นเฉลี่ย 20 นาทีในการทำรายการแต่ละครั้ง ปัญหาการต้องกรอกข้อมูลเดิมซ้ำๆ หลายหน้านี้ จัดเป็น Pain Point ประเภทใดอย่างเจาะจงที่สุด?
- ก. Process Pain Point
- ข. Productivity Pain Point
- ค. Support Pain Point
- ง. Design Pain Point

**เฉลย:** **ก. Process Pain Point**
- **จุดหลอกของข้อสอบ:** โจทย์ระบุว่า "เสียเวลาเพิ่มขึ้น 20 นาที" ทำให้นักศึกษาจำนวนมากรีบตอบ Productivity Pain Point ทันที
- **ทำไมถึงเป็น Process Pain Point:** ต้นตอของปัญหา (Root Cause) เกิดจาก **ขั้นตอนการทำงาน (Workflow/Process) ที่ซ้ำซ้อนและไร้ประสิทธิภาพ** (การบังคับกรอกซ้ำ 4 หน้า) แม้ผลลัพธ์จะทำให้เสียเวลาก็ตาม ข้อสอบที่หลอกลึกจะวัดที่ "แก่นของปัญหา" ไม่ใช่วัดที่ผลกระทบปลายทาง
- **ความต่าง:** Productivity Pain Point เกิดจากความเชื่องช้าของระบบหรือเครื่องมือ (เช่น เว็บโหลดอืด ประมวลผลช้า) แต่ถ้าเกิดจากขั้นตอน/ระเบียบวิธีที่วุ่นวายซ้ำซ้อน จะต้องจัดเป็น Process Pain Point

---

### ข้อที่ 4 (กับดัก: User Persona - Proto-Persona vs Research Persona)
**โจทย์:** ข้อใดต่อไปนี้กล่าวถึง User Persona ได้อย่างถูกต้องตามหลักการทางวิชาชีพ UX?
- ก. Persona ควรสร้างขึ้นจากจินตนาการและความคิดสร้างสรรค์ของทีมออกแบบ เพื่อให้ได้ตัวละครที่มีเอกลักษณ์เฉพาะตัว
- ข. ในหนึ่งผลิตภัณฑ์ควรสร้าง Persona เพียงคนเดียวเท่านั้น เพื่อให้ทีมงานโฟกัสการออกแบบได้ง่ายที่สุด
- ค. Persona เป็นตัวแทนสมมุติของกลุ่มผู้ใช้ แต่ต้องสังเคราะห์ขึ้นมาจากข้อมูลเชิงประจักษ์ของการวิจัยผู้ใช้จริง
- ง. การใส่รายละเอียดของอาหารที่ชอบ ดนตรีที่ฟัง และสัตว์เลี้ยงที่รัก เป็นสิ่งจำเป็นอย่างยิ่งในทุก Persona เสมอ

**เฉลย:** **ค. Persona เป็นตัวแทนสมมุติของกลุ่มผู้ใช้ แต่ต้องสังเคราะห์ขึ้นมาจากข้อมูลเชิงประจักษ์ของการวิจัยผู้ใช้จริง**
- **จุดหลอกของข้อสอบ:** ข้อ ก. มักลวงคนที่เข้าใจคำว่า "บุคคลสมมุติ (Fictional Character)" ผิดไปว่าหมายถึงคิดเอาเองตามใจชอบ, ส่วนข้อ ง. ลวงด้วยเทมเพลตสวยๆ ตามอินเทอร์เน็ต
- **คำอธิบาย:** Persona ต้องมีรากฐานมาจาก **User Research Data** (เช่น สัมภาษณ์ สังเกตการณ์) การใส่รายละเอียดส่วนตัว (ข้อ ง.) ต้องใส่เฉพาะสิ่งที่ "เกี่ยวข้องกับบริบทของผลิตภัณฑ์ (Contextual Relevance)" เท่านั้น หากไม่เกี่ยวถือเป็นข้อมูลขยะที่ทำให้ทีมหลงทิศทาง

---

### ข้อที่ 5 (กับดัก: 4 Types of Pain Points - Design vs Support)
**โจทย์:** ผู้ใช้สูงอายุพยายามสั่งซื้อสินค้าในแอปพลิเคชัน แต่ไม่สามารถดำเนินการต่อไปได้ เนื่องจากปุ่ม "ชำระเงิน" ใช้ฟอนต์สีเทาอ่อนบนพื้นหลังสีขาว และไอคอนรูปตะกร้าสินค้าไม่มีคำบรรยายใต้ภาพ ทำให้ผู้ใช้มองไม่เห็นและไม่เข้าใจว่าต้องกดตรงไหน ปัญหานี้จัดเป็น Pain Point ชนิดใด?
- ก. Productivity Pain Point
- ข. Support Pain Point
- ค. Process Pain Point
- ง. Design Pain Point

**เฉลย:** **ง. Design Pain Point**
- **คำอธิบาย:** Design Pain Point เกิดขึ้นโดยตรงจากความบกพร่องทางสุนทรียภาพ โครงสร้างหน้าจอ หรือ Visual Elements เช่น คอนทราสต์ของสีไม่ผ่านมาตรฐาน (Low Contrast), ขนาดตัวอักษรเล็กเกินไป, หรือการจัดวาง Layout ที่ชวนสับสน

---

### ข้อที่ 6 (กับดัก: User Journey Map - Trigger)
**โจทย์:** ใน User Journey Map ของแอปพลิเคชันเรียกรถพยาบาลฉุกเฉิน "เสียงกระจกหน้าต่างแตกพร้อมกับเสียงคุณแม่ร้องขอความช่วยเหลือจากในห้องน้ำ" จัดเป็นองค์ประกอบใดในแผนผัง?
- ก. Persona
- ข. Trigger
- ค. Action
- ง. Pain Point

**เฉลย:** **ข. Trigger**
- **จุดหลอกของข้อสอบ:** บางคนอาจตอบ Pain Point เพราะเห็นว่าเป็นอุบัติเหตุ
- **คำอธิบาย:** **Trigger (สิ่งเร้า/ตัวกระตุ้น)** คือเหตุการณ์หรือจุดเริ่มต้นภายนอกที่ผลักดันให้ผู้ใช้ต้องเข้าสู่กระบวนการใช้งานระบบ ในกรณีนี้เหตุการณ์ในห้องน้ำคือสิ่งที่ทำให้เกิดความต้องการใช้งานแอปทันที จึงเป็น Trigger ของ Journey

---

### ข้อที่ 7 (กับดัก: 4 Types of Pain Points - Support Pain Point)
**โจทย์:** ลูกค้าซื้อตั๋วเครื่องบินผ่านแอปพลิเคชันออนไลน์ แล้วถูกตัดเงินจากบัตรเครดิตไปแล้ว 2 ครั้ง แต่ไม่ได้รับอีเมลยืนยันตั๋วโดยสาร เมื่อพยายามค้นหาเบอร์โทรติดต่อศูนย์ช่วยเหลือในแอป กลับพบเพียงบอทตอบคำถามอัตโนมัติที่ตอบไม่ตรงคำถาม และไม่มีปุ่มให้ติดต่อเจ้าหน้าที่ตัวจริง ปัญหาของลูกค้ารายนี้จัดเป็น Pain Point ชนิดใด?
- ก. Process Pain Point
- ข. Support Pain Point
- ค. Productivity Pain Point
- ง. Design Pain Point

**เฉลย:** **ข. Support Pain Point**
- **คำอธิบาย:** Support Pain Point คือภาวะที่ผู้ใช้ติดขัดปัญหาในระบบแล้ว **ไม่ได้รับความช่วยเหลือ คำชี้แจง หรือการสนับสนุนที่เหมาะสม (Lack of Assistance/Guidance)** การไม่มีเจ้าหน้าที่ช่วยเหลือหรือข้อมูลติดต่อแก้ปัญหา จัดเป็น Support Pain Point โดยตรง

---

### ข้อที่ 8 (กับดัก: การแปลงปัญหาเป็น How Might We)
**โจทย์:** หากกำหนด POV คือ: *"นักศึกษาจบใหม่ต้องการวิธีเก็บเงินสำหรับฉุกเฉิน เพราะพวกเขาควบคุมค่าใช้จ่ายในการกินเลี้ยงสังสรรค์ไม่ได้"* ข้อใดคือการตั้งคำถาม How Might We (HMW) ที่เหมาะสมที่สุดโดยไม่ตีกรอบความคิดแคบเกินไปและไม่กว้างจนจับต้องไม่ได้?
- ก. เราจะสร้างแอปพลิเคชันล็อกบัญชีธนาคารหลังเวลา 20.00 น. ได้อย่างไร?
- ข. เราจะช่วยให้นักศึกษาจบใหม่สนุกกับการสังสรรค์กับเพื่อนได้โดยไม่กระทบต่อเป้าหมายเงินออมฉุกเฉินได้อย่างไร?
- ค. เราจะทำให้เยาวชนทุกคนในประเทศไทยมีฐานะทางการเงินที่ร่ำรวยได้อย่างไร?
- ง. เราจะส่งการแจ้งเตือน SMS เตือนสติตอนเที่ยงคืนได้อย่างไร?

**เฉลย:** **ข. เราจะช่วยให้นักศึกษาจบใหม่สนุกกับการสังสรรค์กับเพื่อนได้โดยไม่กระทบต่อเป้าหมายเงินออมฉุกเฉินได้อย่างไร?**
- **จุดหลอกของข้อสอบ:** ข้อ ก. และ ง. เป็น HMW ที่ **แคบเกินไป (Too Narrow)** เพราะระบุ Solution ลงไปแล้ว (ล็อกบัญชี, ส่ง SMS) ทำให้หมดโอกาสคิดไอเดียอื่น ส่วนข้อ ค. เป็น HMW ที่ **กว้างเกินไป (Too Broad)** จนไม่สามารถแปลงเป็นฟีเจอร์ที่จับต้องได้

---

### ข้อที่ 9 (กับดัก: ความสัมพันธ์ระหว่าง Persona กับ User Journey Map)
**โจทย์:** หากบริษัทมีกลุ่มลูกค้าเป้าหมาย 2 กลุ่ม คือ "นายสมคิด (ช่างเทคนิคสูงอายุ ไม่คุ้นเคยกับเทคโนโลยี)" และ "น้องฟ้า (นักเรียนมัธยม ติดสมาร์ทโฟนตลอดเวลา)" ในการทำ User Journey Map สำหรับบริการเดียวกัน ข้อใดคือแนวปฏิบัติที่ถูกต้องที่สุด?
- ก. รวมทั้งสองคนเข้ามาอยู่ใน Journey Map แผ่นเดียวกัน โดยใช้ค่าเฉลี่ยของอารมณ์และขั้นตอน
- ข. แยกทำ User Journey Map เป็น 2 ชุดแยกจากกันตามแต่ละ Persona
- ค. ทำ User Journey Map เฉพาะของน้องฟ้า เพราะเป็นกลุ่มคนรุ่นใหม่ที่มีโอกาสใช้แอปมากกว่า
- ง. ปรับลดขั้นตอนของระบบให้สอดคล้องกับนายสมคิดคนเดียวเท่านั้น

**เฉลย:** **ข. แยกทำ User Journey Map เป็น 2 ชุดแยกจากกันตามแต่ละ Persona**
- **คำอธิบาย:** User แต่ละกลุ่มมีเป้าหมาย ความรู้พื้นฐาน (Mental Model), จุดติดขัด (Pain Points) และอารมณ์ที่แตกต่างกันอย่างสิ้นเชิง การนำมารวมกันในแผนผังเดียว (ข้อ ก.) จะทำให้ข้อมูลเจือจางและไม่สะท้อนความเป็นจริง จึงต้อง **แยกทำ 1 Journey Map ต่อ 1 Persona เสมอ**

### ข้อที่ 10 (กับดัก: Empathy Map - Thinks vs Feels)
**โจทย์:** ในระหว่างการใช้งานแอปพลิเคชันเพื่อกู้เงินด่วน ผู้ใช้แสดงสีหน้าวิตกกังวลและมีเหงื่อซึมที่ฝ่ามือ พร้อมกับในใจเกิดความคิดว่า *"ถ้าเพื่อนร่วมงานรู้ว่าฉันกู้เงินพวกนี้ พวกเขาต้องมองฉันไม่ดีแน่ๆ"* ประโยคความคิดที่เกิดขึ้นในใจนี้ ควรบันทึกไว้ในช่องใดของ Empathy Map?
- ก. Feels
- ข. Thinks
- ค. Says
- ง. Does

**เฉลย:** **ข. Thinks**
- **จุดหลอกของข้อสอบ:** ข้อสอบหลอกด้วยคำว่า "วิตกกังวล" (ซึ่งเป็น Feeling) แต่ถามเจาะจงที่ **"ประโยคความคิดในใจ"**
- **คำอธิบาย:** ความวิตกกังวล/เหงื่อซึม จัดอยู่ในช่อง **Feels** (อารมณ์และสภาวะจิตใจ) แต่ประโยคตรรกะหรือความคิดในสมองที่ว่า *"ถ้าเพื่อนร่วมงานรู้...ต้องมองไม่ดี"* จัดอยู่ในช่อง **Thinks** (กระบวนการคิด ทัศนคติ และความเชื่อภายใน)
