## Slide Page 22

Usability Test Design Process

### รายละเอียดกระบวนการ: Usability Test Design Process (ขั้นตอนการออกแบบการทดสอบ)
1. **Define Objectives:** กำหนดเป้าหมายการทดสอบ สมมติฐาน และตัวชี้วัดความสำเร็จ
2. **User Profiles & Screener:** กำหนดโปรไฟล์กลุ่มเป้าหมาย และสร้างแบบสอบถามคัดกรอง (Screener)
3. **Scenario & Task Design:** ออกแบบสถานการณ์จำลองและภารกิจที่สมจริง (Real-world scenarios) ไม่ชี้นำคำตอบ
4. **Metrics Selection:** เลือกเกณฑ์วัดผลเชิงปริมาณ (เช่น Time on Task, Success Rate) และเชิงคุณภาพ (เช่น SUS, Think-Aloud)
5. **Pilot Testing:** ทดสอบระบบนำร่องกับทีมภายในเพื่อตรวจจับบั๊กและปรับแต่งเวลา
6. **Execution & Moderation:** ดำเนินการทดสอบ สังเกตพฤติกรรม บันทึกวิดีโอ และเก็บข้อมูลแบบ Think-Aloud
7. **Synthesis & Debrief:** รวบรวมผล วิเคราะห์หา Usability Issues และจัดลำดับความสำคัญในการแก้ไข

### รายละเอียดประเภทข้อมูล: Qualitative vs Quantitative Usability Data
- **Qualitative Data (ข้อมูลเชิงคุณภาพ):** ตอบคำถามว่า "ทำไมเกิดปัญหานี้ และผู้ใช้รู้สึกอย่างไร"

- **Quantitative Data (ข้อมูลเชิงปริมาณ):** ตอบคำถามว่า "เกิดปัญหาบ่อยแค่ไหน และมีประสิทธิภาพเพียงใด"
  * แหล่งข้อมูล: Task Completion Rate (อัตราความสำเร็จ), Time on Task (เวลาเฉลี่ยในการทำภารกิจ), Error Rate (จำนวนครั้งที่กดผิด), Single Ease Question (SEQ), System Usability Scale (SUS)

## Slide Page 60

Mapping the Flows 
Happy vs Unhappy path

### รายละเอียดการทำ Mapping the Flows: Happy Path vs Unhappy Path
- **Happy Path:** เส้นทางการใช้งานในอุดมคติที่ราบรื่น ไร้ข้อผิดพลาด ผู้ใช้ทำภารกิจสำเร็จตั้งแต่ต้นจนจบโดยตรง
- **Unhappy Path (Edge Cases & Error States):** เส้นทางที่เกิดข้อผิดพลาด เช่น กรอกข้อมูลผิดรูปแบบ, สัญญาณเน็ตหลุด, สินค้าหมดสต็อก, ระบบประมวลผลล้มเหลว
- **หลักการสำคัญของ UX:** การออกแบบที่ดีต้องให้ความสำคัญกับ Unhappy Path ไม่ยิ่งหย่อนไปกว่า Happy Path เพื่อช่วยให้ผู้ใช้กู้คืนจากข้อผิดพลาด (Error Recovery) ได้อย่างรวดเร็วและไม่หงุดหงิด
